## 0. 结论速览

1. **起步是 OP 发的**：seg9 内原厂 LS_01 无一次 RESUME（0 次），OP 代发 **3 次** RESUME 脉冲
   （565.06 / 570.86 / 573.98 s，`LS_Tip_Wiederaufnahme` 上升沿 src≠2），并同时把 OP 侧 `ACC_05.Anhalten` 1→0。
2. **为什么"停住了又起步"**：融合后的 `dRel` 被钉死在 **10.09 m**（`t(188)×max(v,5)=2.018×5`），而真实车距
   从 6.2 m 一路缩到 4.0 m；planner 以为还有 10 m → 持续给 +0.2 m/s² 收拢车距 → 撞上 SnG 阈值 → RESUME →
   原厂放行 → 车动 → 又停 → 再来一次。seg9 发生 **2 段蠕行**（566.1–568.9、575.4–576.4）。
3. **st=6 是原厂"可恢复的 ACC 系统故障"**（DBC `VAL_ 269`：6 = `reversibler_Fehler_im_ACC_System`），
   出现在第 3 次 RESUME（573.98）后 **0.9 s**（574.89），同时 `Relevantes_Objekt` 1→0；之后原厂 idx 立刻
   "复活"（188→77），OP 在视觉 3.5–4.0 m 的距离上给了 **+1.0 m/s²**，驾驶员 575.73 踩刹车才停住（OP soft-disable）。
   即：**不是"原厂 ACC 禁止起步"，是原厂被 OP 的反复 RESUME + 矛盾请求打进了可恢复故障态。**
4. **`ACC_Display_Prio` 不是前车格数信号**（见 §6）：它是 `ACC_02` 的 2 bit 显示优先级位（44|2，0–3），
   实测在 idx 冻结期间还 3↔2 跳（跟着"车距在收窄/拉开"变），不携带距离。格数由用户在 `ACC_Gesetzte_Zeitluecke`
   里的 DIST 设定 + `Abstandsindex/Relevantes_Objekt` 决定。
5. **方案选择：走 B（融合 + 紧要节点保守化），不建议 A**；A 的一个致命点是把"冻结的 idx"当真实
   目标距离切过去（今天中午 idx=188 会变成 10 m 的假目标）。理由与补强见 §4/§5。

## 2. 机制：融合距离被"钉死"

```
idx=188（静止后 hold 值）
 → stock_drel = t(188) × max(v,5) = (0.008969×188+0.332) × 5 = 2.018 × 5 = 10.09 m   ← 与日志 10.1 m 逐帧一致
 → rel = |d_vis − 10.09| / 10.09（6.2 m 时 rel=0.39 > MACAN_A2_REL_TH=0.30）→ w=1.0 → fused = 10.09 m
 → planner: 前车 10 m、vRel≈0 → 小幅正加速度收拢 → 进入 SnG 阈值 → RESUME
 → 车动 → 视觉 vRel 转负 → 停 → 循环
```
问题不在 A1/A2 的权重，而在**低速等效速度 `max(v, 5)`**：静止时它把"时距"折算成 5 m/s 的距离，
对 188 号索引给 10.09 m，而真实距离是 6.2 m（偏低 63%）。

## 3. 原厂 idx 在静止时到底动不动？（回答用户质疑）

| 片段 | 工况 | 原厂 idx 行为 |
|---|---|---|
| 91 seg9 562.8–574.9 | 跟停**静止目标**（公交车），本车蠕行靠近 | **冻结 12.2 s**（恒 188），但 `rel=1`、`Display_Prio` 仍在 3↔2 跳 → ECU 活着，只冻了 idx |
| 7a seg4 / seg7 / seg11 | 跟停静止目标 | **冻结**（恒 251，28.4 s / 34.8 s / 2.2 s），视觉 4.4–5.8 m |
| 7a seg8 / seg9 | 静止但目标在远处（视觉 28–32 m）或在动 | **不冻结**（87 / 17 个不同值，709→722 / 849→861） |
| 7a seg2 39.5–44.8 | 静止起步加速（视觉 6.9→20 m） | **不冻结**（181→400，与原厂调节同步） |
| 7a seg6 / 7b seg5 | 静止/极低速、目标 5 m 级 | **不冻结**（25 个不同值，94→104 等） |

**结论（用户的怀疑是对的，但要分情况）**：
- 不是"车一停 idx 就不算"，而是**原厂在自己的跟停保持（Anhalten/hold）状态、且目标静止时，Abstandsindex 会保持最后一次值**；
  目标在动/在远处、或原厂正在调节（加速/蠕行）时，idx 照常更新。
- 因此：**"同一 idx 连续 N 帧不变"不能单独当失效判据**（行驶中常量 idx 很常见）；必须叠加
  "存在相对运动 + 视觉距离沿相对速度方向单调变化"（用户 #3 的思路，采纳）。
- 更关键的是：**hold 值本身不能当距离用**——7a seg4 的 251 与 91 的 188 在同一物理量级上互相矛盾
  （251↔视觉 4.4 m，188↔视觉 6.2 m），说明 idx 不是 (d, v) 的单值函数，冻结值只反映"当时那一下"。

## 4. 低速 idx ↔ 距离：实测数据与标定建议

实测样本（`idx, v, 视觉距离`，视觉 = `modelV2.leadsV3[0].x`，prob>0.5；route 91 的视觉距离与
"积分车速≈12 m / 视觉闭合 10.4 m"自洽，可信）：

| 来源 | v (m/s) | idx | 视觉 d (m) | idx/30 | idx/20 | 现状公式 `t(idx)·max(v,5)` |
|---|---|---|---|---|---|---|
| 91 减速 | 4.79 | 244 | 16.6 | 8.1 | 12.2 | 12.1 |
| 91 减速 | 2.96 | 223 | 11.3 | 7.4 | 11.2 | 6.9 |
| 91 减速 | 2.35 | 209 | 9.8 | 7.0 | 10.5 | 5.5 |
| 91 减速 | 1.83 | 196 | 8.7 | 6.5 | 9.8 | 3.8 |
| 91 停稳 | 0.7 | 188 | **6.2** | **6.27** | 9.4 | **10.09** ← 错得最狠 |
| 91 故障后 | 0.5 | 77 | 3.5–4.0 | 2.6 | 3.9 | 5.1 |
| 7a seg2 加速 | 0.32→4.44 | 181→400 | 6.9→20.0 | 6.0→13.3 | 9.1→20.0 | — |
| 7a seg4 静止 | 0.0 | 251(冻结) | 4.4 | 8.4 | 12.6 | 12.9 |

观察：
1. **现状公式在 v<5 时系统性偏远**（`max(v,5)` 的锅），静止时最严重（10.09 vs 6.2）。
2. 用户的 **`d = idx/30`** 在 91 的停稳点非常准（6.27 vs 6.2/6.15），但在 7a seg4（251↔4.4 m）、
   7a seg2 加速段（idx/d≈20–27 且在变）不成立 → **idx/30 只是"停稳点"附近的好近似**，不是通用式。
3. 结论：低速映射无法用一个常数 K 精确拟合；**用 K=20（偏保守：算出来的距离偏小）做"下钳"** 更安全，
   因为我们的控制目标是"不要以为车距够远"，而不是"精确估计车距"。

**建议的低速分支（拟案，未实施）**
```
# v > 5 m/s：保留现有 B1 表（t = 0.008969·idx + 0.332, d = t·v）
# v <= 5 m/s：视觉为主，idx 只能"把距离往下拉"，不能往上抬
d_idx_low = idx / MACAN_IDX_LOW_K          # K=20（保守），仅当 idx 有效且新鲜
d_used    = min(d_vis, d_idx_low) if idx_ok else d_vis
```
（这条规则对 §3 的三种实测工况全部给出安全结果：91 停稳 → 取视觉 6.2；7a seg4 → 取视觉 4.4；
91 故障后 idx=77 → 取 3.85 vs 视觉 3.5 → 取 3.5。）

## 5. 方案 A vs 方案 B

| 维度 | A：纯视觉为主，只有"视觉无车 && 0<idx<1021"才用 idx 换算 | B：保留融合 + 紧要节点保守化 |
|---|---|---|
| 今天中午的死循环 | 能解决（不再用冻结 idx） | 能解决（min 规则让视觉赢） |
| 前车静止/近距安全 | 依赖视觉；视觉在 4–16 m 这类场景实测可信（§4），但**静止目标丢失率**是视觉弱项 | 原厂 idx 只要有效就仍在下钳，多一层兜底 |
| "视觉无车但原厂有车" | 会切 idx → 若遇 hold 值，会把 10 m 假目标当真目标（**新风险**） | 用 min + 新鲜度校验，同样能覆盖且不会凭空造远距离目标 |
| 行驶中常量 idx 的误判 | 无（A 基本不用 idx） | 靠 §6.2 的"相对运动 + 视觉同向变化"判据规避，不会退化成纯视觉 |
| 中高速（>5 m/s）融合收益 | 放弃（原厂 idx 在中高速标定最好，PLANB 文档 RMS 0.61 s） | 保留 |
| 体感风险 | 源切换（视觉↔idx）在 5–15 m 会跳 | min() 只在"更近"方向动作，不会把车距判远 |
| 实现量 | 小 | 中（多两个判据 + 阈值） |

**推荐 B**，外加用户提的 ②（起步管控）与"车距过远用蠕行而不是 RESUME"，以及下面 3 点补强：

- **B-①补强**：min 规则不只用于"低速或 TTC<3 s"，还应加 **"前车静止（|vLead|<0.3）"** 与
  **"本车处于 standstill/低速段"** 两个触发条件；且 `d_idx_low` 必须先过 §6.2 的有效性校验（否则 idx 一旦
  偏小会误刹）。
- **B-②补强（起步管控）**：条件应包含"前车速度>0 且持续 ≥1 s"**且**"前车不是通过原厂 hold 值伪造的"——
  建议直接用**视觉 vLead 与原厂 ACC_04 前车速度中较大的那个**，并要求 `rel==1`；同时**前车静止时无条件禁止
  RESUME**（今天 3 次 RESUME 全部发生在前车静止时，这是 st=6 的直接诱因）。
- **B-③补强（防 st=6）**：同一停车周期内 **RESUME 最多 1 次**（现在有 3 s 冷却，但今天 565/571/574 三次
  间隔 <10 s 且都没带来有效起步）；且"停车保持态下 OP 的 `accel` 必须 ≤0，除蠕行意图外不给正加速度"——
  今天 566–574 全程 +0.2 m/s²，是与原厂 hold 直接对抗的请求。

## 6. 其余待办（拟案，未实施）

### 6.1 idx 有效性校验（用户 #3，采纳并细化）
判据（**三个都要**，避免把行驶中的常量 idx 误杀）：
1. `rel == 1` 且 `0 < idx < 1021`（现状）**且**最近 `T_fresh=0.5 s` 内 idx 有更新（`idx != idx_prev`）；
2. **存在相对运动**：`|v_rel| > 0.3 m/s`（v_rel 用原厂 ACC_04 前车速度−vEgo，缺失时用视觉 vRel）；
3. **方向一致性**：idx 在该窗口内不变，而视觉距离沿 `v_rel` 方向单调变化累计 > 0.5 m × 连续 ≥3 帧。
全部满足 → 判 idx 为 **stale/hold**：本次融合回退视觉，并打 `MacanIdxStale` 计数（日志可视化，先不加 UI）。
反向条件（idx 恢复有效）：idx 重新出现变化 **或** 视觉与 idx 换算距离重新进入 30% 带内。

### 6.2 SnG 起步（用户 #4）
- RESUME 门控（在现有 `update_stop_and_go` 的距离/挡位/`st==3` 之上追加）：
  `前车速度max(视觉 vLead, 原厂 ACC_04) > 0 持续 ≥1 s` && `d_used > max(6 m, MacanStartStopDistance)` &&
  `rel==1` && 前车非静止 && 本停车周期 RESUME 次数 < 1。
- **不再用 RESUME 修车距**：车距过远（`d_used > 目标车距+1 m`）且前车静止时，走"怠速蠕行"：
  释放原厂 hold（`loes` 窗口，沿用现有事件化逻辑）**不发 RESUME**，只给限幅正加速度
  （`accel ≤ +0.3 m/s²`，目标 0.5–0.8 m/s 爬行），`d_used ≤ 3 m` 或前车动即退出。
  依据：seg9 566.1–568.9 实测 OP `accel=+0.2` 就能让车从 0 爬到 1.0 m/s（原厂那时还挂着 `Anhalten=1`），
  说明融合模式下"OP 正加速度 + 原厂放行"足以蠕行，不需要 RESUME。
- `d_used` 一律取 `min(视觉, idx/K)`（同上），避免蠕行目标算错。

### 6.3 显示层：让 bus128 的 ACC_02 至少覆盖 bus2（用户第 4 点）
- 现状实测（91 seg9，1 s=25 格）：原厂 ACC_02 **25 Hz / 1500 帧**，OP 代发 **16.7 Hz / 999 帧**
  （`ACC_HUD_STEP=6`）。按 40 ms 格比较：原厂"有前车"1430 格、OP 1447 格；**原厂有 / OP 无 49 格**
  （集中在 541.8–544.1 s，正是目标刚出现、视觉还没锁上的那段），**OP 有 / 原厂无 66 格**（544.5–546.1 s）。
- 两处修：① `ACC_HUD_STEP` 6→4（16.7→25 Hz，与 bus2 同频）；② radard 侧"**合成 lead**"：
  视觉无 lead 但 `rel==1 && 0<idx<1021` 时，用 `dRel = idx/K`、`vLead = 原厂 ACC_04 前车速度` 造一个 lead
  （`radar=True`）。这样"仪表 = 控制"的 2.A 语义不变，同时还满足"原厂有 ⇒ OP 也有，且更丰富"。

### 6.4 `ACC_Display_Prio`（回答用户提问）
- DBC：`ACC_02` `SG_ ACC_Display_Prio : 44|2@1+ [0|3]`，接收方未声明 → 显示优先级选择位，**不含距离**。
- 仪表"前车格数"由 `ACC_Gesetzte_Zeitluecke`（用户 DIST 设定值）+ `Abstandsindex`/`Relevantes_Objekt` 决定。
- 实证反证：91 seg9 在 idx 冻结的 12.2 s 里，原厂 `Display_Prio` 仍在 3↔2 跳（565.10、570.89 …），
  而格数显示期间没有变化 → Prio 是"车距在收窄/拉开"这类状态位，不是格数。
- 现状 OP 对 Prio 仍透传原厂（2026-08-22 为避免 st=6 刻意为之），维持不动。
