## 0. 结论（先给答案）

1. **zl=4（本车常用档）的旧结论被证实**：冻结帧剔除 + 同目标配对后，tzl4 = **0.00777·idx + 0.298**
   （n=95,814，RMS 0.59 s），与 0910 登记的 0.00790·idx+0.280 几乎一致 → 现行 B1
   （0.008969·idx+0.332）在 zl=4 下 **系统性高估时距 ~13%**（米级 RMS 6.94 m → 5.60 m）。
2. **zl=3 的旧结论被推翻**：旧表 0.00848·idx+0.584；本次 **0.00987·idx+0.222**（n=8,114，RMS 0.47 s）。
   原因是旧的 zl 分层用了含冻结/低速样本的池子，而冻结样本**恰好集中在低速/停车段**（见 §2）。
3. **但本轮不建议改 `macan_calib` 系数** —— 改准后会**反转融合语义**（§4）：移动域"雷达改近"采纳率
   会从 **13.7% 跳到 44.4%**（稳态段 9.9% → 40.0%）。也就是说：现在"视觉主导、雷达几乎不介入"
   这个实际效果，是 **B1 的 +13% 高估在顶着**；把标定改准等价于把语义改成"取两者更近者"。
   要同时拿到"准标定"和"视觉主导"，必须**同时改门**（见 §5）。
4. **冻结帧确实不进标定，而且不需要额外豁免机制**：实测 176 段 1,035,404 帧里冻结帧占 **32.4%**，
   其 `vEgo` 中位数 **0.00 m/s** → 冻结帧天然全部落在 v<2 m/s 的静止域；
   移动域标定（v≥2 稳态）里**一个冻结样本都没有**。所以"低速另配表"这件事真正的阻塞
   不是样本被污染，而是 §已拍板结论（静止域无静态映射）——本轮不改变该拍板。
5. zl 分表（B4 双表）**现在做不了**：`radard.py` 在独立进程，拿不到 `CS.stock_zeitluecke`
   （那是 carstate 的进程内属性，cereal 里没有对应字段；`pcmCruiseGap` 未在本车填充）。
   先要决定要不要为它加 cereal 通道，再谈分表。

## 1. 方法（口径必须写清楚，否则又是"绕圈"）

- 数据：本机 realdata **176 段**（00000002/03/04/49/7a/7b/91 全量），
  配对样本 **1,035,404**（每帧 idx 有效、prob>0.5、1<d_vis<150、10<idx<1020）。
- 单一源：`macan_route_lib_0910.parse_segment`（② 修好后 **idx/d_vis/v_vis 与独立解析器 0 误差**），
  新增 `v_ego` 字段（schema 3），标定实验用 `carState.vEgo` 真值而非 0x103 轮速。
- **冻结判定**（用户拍板口径）：`vEgo < 2 m/s` 且 `idx` 静默 ≥ 0.5 s → 该帧为冻结帧，**不允许进入标定**。
- 同目标配对门：`prob > 0.5`、`|vLead_vis − vEgo| ≤ 0.5 m/s`（稳态跟车，排除接近/拉开过程）、
  视觉去重（modelV2 ~20 Hz vs carState 100 Hz，只有视觉值变化的帧计入）。
- 两种估计口径都报：
  - **距离域（主口径）**：`d = (a·idx + b)·v`（最小二乘，特征 [idx·v, v]，单位米 —— 直接决定 dRel 误差）；
  - **时距域（与旧文档可比）**：`t = a·idx + b`，`t_meas = (x0 − off)/v`。
- 参考系：`off` 取 0 / 1.52 / 2.5 三档做敏感性；**结论只用斜率**，截距不可辨识（见 §3）。

## 2. 结果

### 2.1 主结果（v≥4 m/s、稳态、按 zl 分层）

| 分层 | n | 时距域拟合 | 距离域拟合 | 距离 RMS（拟合 / B1） |
|---|---|---|---|---|
| zl=4 | 95,814 | **0.00777·idx + 0.298** | (0.00800·idx + 0.248)·v | **5.60 m** / 6.94 m |
| zl=3 | 8,150 | **0.00987·idx + 0.222** | (0.01001·idx + 0.074)·v | **3.67 m** / 3.79 m |
| 混合(不分档) | 103,964 | 0.00782·idx + 0.319 | (0.00804·idx + 0.252)·v | 5.55 m / 6.75 m |

- 两档斜率相差 **25%**（0.0078 vs 0.0099），现行 B1 = 0.008969 **落在两者之间、偏向 zl=3**，
  但本车样本里 zl=3 只占 8%（8.1k / 104k）→ 现行表对本车常用档（zl=4）**偏高**。
- 一致性检查：zl=4 拟合值 vs 旧结论 0.00790·idx+0.280 → 斜率差 1.6%、截距差 0.018 s，**独立方法复现**。

### 2.2 分速度带（v≥2 稳态、zl=4）

| v 带(m/s) | n | 距离域 a | b | 比值中位(拟合/实测) |
|---|---|---|---|---|
| 2–4 | 11,940 | 0.00981 | +0.475 | 0.995 |
| 4–8 | 30,003 | 0.00750 | +0.329 | 1.004 |
| 8–15 | 51,482 | 0.00778 | +0.295 | 1.016 |
| 15–30 | 14,329 | 0.00882 | +0.071 | 1.006 |

斜率不是单调的（2–4 m/s 带明显更陡）→ 单一仿射表在低带会偏；但 4–30 m/s 核心带稳定在
0.0075–0.0088，**都低于 B1 的 0.00897**。

### 2.3 参考系敏感性（v≥4 稳态、zl=4）

| off | 距离域 a | 距离域 b | 时距域 t |
|---|---|---|---|
| 0.00 | 0.00798 | +0.376 | 0.00771·idx+0.487 |
| 1.52 | 0.00800 | +0.248 | 0.00777·idx+0.298 |
| 2.50 | 0.00801 | +0.166 | 0.00781·idx+0.176 |

**斜率对参考系几乎不敏感（±0.4%），截距几乎线性吸收 off** → 斜率可信、截距不可辨识。
这也是为什么"abstands 表的截距"历史上怎么拟合都对不上：它主要由我们选的参考系决定。

## 3. 冻结帧证据（回答"idx188 那类样本该不该进标定"）

| 项 | 数值 |
|---|---|
| 总帧（176 段） | 1,035,404 |
| 冻结帧（v<2 且 idx 静默 ≥0.5 s） | 335,427（**32.4%**） |
| 冻结帧 vEgo 中位 | **0.00 m/s** |
| 移动域（v≥2）样本中的冻结帧 | **0**（构造上不可能：冻结前提就是 v<2） |
| 静止域样本中的冻结帧 | 90,766（占静止域 60%） |

结论：用户那句"idx188 的视觉 4.13/10.09 是冻结帧、不该进标定"**成立且已被机械保证** ——
冻结样本全部落在静止域，移动域标定天然干净。真正的取舍仍是既有拍板：
"静止域不为它另配静态表"（因为同一 idx 在静止域对应 4.1–7.1 m，非函数关系）。

## 4. ⚠️ 关键发现：改准标定会把融合语义从"视觉主导"变成"取更近者"

离线重放 `radard.py` 现行门（`d_vis = x0 − 1.52`；`0 < stock_drel < d_vis` 且
`d_vis − stock_drel ≤ max(0.25·d_vis, 2.0)`），在 176 段全集上统计采纳率：

| 表 | 静止 v<2 | 移动 v≥2 | 移动+稳态 | 冻结帧 |
|---|---|---|---|---|
| **B1 现行**(0.008969/+0.332) | 0.18% | **13.66%** | 9.93% | **0.00%** |
| 候选 zl4(0.00800/+0.248) | 0.47% | **44.44%** | 39.96% | **0.00%** |
| 候选 zl3(0.00987/+0.222) | 0.18% | 9.22% | 6.99% | 0.00% |

- 冻结域在三个候选下**全是 0.00%** → seg9 那类"冻结值改远/改近"的安全属性**不靠系数，靠 max(v,5) 守卫**（与 0910 doc §4 一致）。
- 但移动域：换用"标定正确"的 zl4 系数后，雷达将有 **44%** 的帧比视觉更近 → 被采纳。
  这不是 bug，而是**两者测的是同一个量、谁更近谁赢**的必然结果；
  也就是说当前的"视觉主导"实际是 B1 的 +13% **系统性高估**在代为实现。
- 反向检查：zl3 系数（比 B1 更陡）会把采纳率压到 9.2% → 说明该指标对系数极敏感，
  **任何系数改动都必须先跑这张表**（本工具已固化该检查）。

## 5. 拍板与下一步

| 项 | 决定 | 依据 |
|---|---|---|
| 用新斜率替换 `macan_calib.MACAN_B1_T_A/B` | **不做（本轮）** | §4：会同时把移动域雷达采纳率 13.7%→44.4%，属语义变更，不是纯 bugfix；必须与门同步改 + 路试 |
| zl=3/zl=4 分表（B4 双表） | **暂不做** | §0.5：`radard` 进程拿不到 zl（需先决定是否加 cereal 通道）；且分表本身仍受 §4 的采纳率问题约束 |
| 静止域低速表 / 冻结豁免 | 维持既有拍板（不做） | §3：冻结样本全在静止域且无静态映射；移动域标定天然干净 |
| "斜率已可信"这条结论 | **采纳** | §2.3：斜率对参考系不敏感、两独立方法复现（0.0078 vs 0.00790） |
| 若要改表（下一轮） | 前置条件：① 同提交内收紧 `MACAN_FUSE_REL_GATE`/`MIN_GAP` 使采纳率回到现水平；② 离线先用本轮工具跑采纳率表；③ 路试对照 | §4 |

**唯一可执行的下一步**：先定"融合门要什么语义"——若确实要
「视觉主导、雷达只在**明显**更近时介入」，则门要从 `Δ ≤ gate` 改成
`Δ ≥ 门槛`（例如要求雷达比视觉近 ≥1 m 才采纳），再谈改系数；否则改表 = 改成 min(vision, radar)。
