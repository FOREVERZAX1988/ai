# Macan 纯OP点火报错 —— 任务3：定位"车辆→雷达"方向在纯OP失联时消失的CAN2周期应答帧 (0916)

> 分支：macan-long-0915/0916 ｜ 数据源：route 0075(纯OP/坏) vs 0078(融合/好) seg0 rlog 全量逐帧
> 方法：capnp 解析 rlog 原始 can 事件，按 src(物理总线捕获源) 分治统计 + 9.25s 故障时刻前后逐帧比对
> 核心问题：修复方向1 想模拟"车辆→雷达应答"，必须先精确定位**到底是哪一组帧在纯OP消失**。

---

## 一、任务3 一句话结论
**在雷达总线(CAN2, panda 记作 src=2)上，纯OP(坏)与融合(好)**出现**在 src=2 上的"车辆/OP 源"周期帧集合完全相同——没有任何车辆→雷达方向的应答帧在纯OP下消失。**
真正消失的，是**物理总线的"多节点回环"**：融合模式下 radar 与车辆 ACC 网关在 CAN2 同一物理总线，radar 能看到自己的 ACC 指令帧被网关/总线应答（往返回环），因此保持待命；
纯OP relay 隔离后，CAN2 变成 **radar 单节点孤岛**，radar 只能看到自己发的 ACC 帧、看不到任何往返，约 6s 后（9.251s）内部看门狗判定"ACC 网络通信不完整"→ 自报故障。

## 二、决定性数据（任务3 扫描结果）

### 2.1 src=2(radar总线) 上"车辆/OP 源"帧集合 好/坏对比
对 src=2 上同时出现在车辆源(src=0/OP src=128)的地址取交集：
- **GOOD-0078 的 bus2 车辆/OP帧 = BAD-0075 的 bus2 车辆/OP帧（完全一致，差集为空）**
- BAD 额外只有点火诊断探测帧（0x700~0x7E4、0x18DAxxF1、0x24B），为 UDS 诊断会话，非周期性应答。
- **结论：不存在"某一组车辆→radar 周期帧在纯OP消失"——帧一个都没少。**

### 2.2 ACC 帧在雷达总线(src=2)上的计数（好/坏几乎一致）
| 帧 | GOOD-0078 src=2 | BAD-0075 src=2 |
|----|-----------------|----------------|
| 0x10D (ACC_05) | 3065 | 3062 |
| 0x117 (ACC_10) | 3065 | 3062 |
| 0x127 | 3065 | 3063 |
| 0x30C (ACC_02) | 1532 | 1531 |
| 0x324 (ACC_04) | 1532 | 1531 |
→ radar 的 ACC 帧在纯OP下**照常发送、未中断**，不是"信号消失"。

### 2.3 故障后(≥9.3s) radar 总线字节 好/坏 决定性差异
| 信号 | BAD-0075 纯OP(故障) | GOOD-0078 融合(健康) |
|------|---------------------|----------------------|
| 0x324 b7 | **0x12(18)** charisma 故障 | **0x0a(10)** 待命 |
| 0x10D b7 | **0x8e(142)** 故障/不可用 | **0x84(132)** 健康 |
| 0x30C b7 | 0(未动摇) | 0 |
→ radar 在纯OP 约9.25s 起持续自报故障状态，但**帧照发**——所以不是"帧消失"，是雷达**自我判定**为故障。

### 2.4 OP 反向发送到 CAN2 的方向(src=130)不含 ACC 应答
- src=130(OP→CAN2 发送) 在好/坏路由中 **均不含 0x10D/0x117/0x127/0x30C/0x324**，只有 0x392(OP 自身状态)及车辆底盘帧。
- 融合模式这些 ACC 帧的"往返"由**车辆 ACC 网关在物理总线直接参与**，panda 只捕获到 radar 单份；纯OP 则完全没有第二份。

## 三、物理机制链（任务3 修正后的根因）
1. 纯OP 纵向模式 safety(VOLKSWAGEN_MLB_LONG_TX_MSGS, opendbc/safety/modes/volkswagen_mlb.h)：
   OP 自己代发 ACC_02/05/04 到 **bus0(车辆)**，LS_01 到 **bus2(radar 总线)**；check_relay=true 且 relay 在纯OP 状态。
2. relay 隔离后，CAN2 物理总线与车辆 ACC 网络断开 → radar 所在 CAN2 成为**单节点**（radar 只发不收，无任何它方应答/回环）。
3. radar 内部通信看门狗计时（点火自检 0→1 握手约 3s 完成后，约 6s 后即 9.251s）判定"ACC 网络不完整"→ 自报故障：
   charisma 0x324 b7: 0x0a→0x12，ACC_05 0x10D b7: 0x84→0x8e，ACC_02 状态→7。
4. 该故障状态被 OP 桥接后反射到 bus128/仪表 → 仪表 ACC 报错。与用户 0075 观测完全吻合。

## 四、对修复方向的修正建议
- **否定"模拟单组车辆→radar 周期应答帧"的低成本假说**：因为不是一个帧消失，而是**整个 CAN2 物理网络从"多节点"退化为"radar 单节点"**。
- 修复方向调整：
  1. **（最贴合机制）保持 CAN2 有"多节点感觉"**：由 OP 在 CAN2(bus2) 上周期性**转发作废/回环**一组"车辆侧应答"帧（如把 OP 在 bus0 代发的 ACC_02/04/05 也**镜像回发到 bus2**，模拟网关参与），让 radar 觉得总线上有它方在收发 → 保持待命不报故障。
     - 注意 safety VOLKSWAGEN_MLB_LONG_TX_MSGS 需在 bus2 加 ACC_02/04/05 发送许可（当前只在 bus0）。
  2. 或**诊断会话主动停用 radar**（UDS，复杂）。
  3. 或 OP 层面忽略 radar 故障位、强制显示待命（radar 内部仍报 st=7 的兼容性需台架验证）。
- **本任务证据支持方向 1 作为首选**：缺失的不是某个握手帧，而是"总线多节点回环"；在 bus2 上把 OP 的 ACC 指令回环一份即可重建该感觉。

## 五、与其他任务的衔接
- 任务1(HANDSHAKE_CONCLUSIONS)判断"无单一握手帧、根因=relay隔离后 radar 失联应答" → 本任务把"失联应答"精确化为"**CAN2 从多节点退化为单节点，radar 无法感知总线有它方应答**"。
- 任务2(0x127/0x395)维持：两者均非握手/应答帧，本任务再次验证其在好/坏路由字节一致、不参与故障判定。
- 0x127 恒为 0020493c78ee0000(常值) 在故障前后不变 → 进一步坐实非握手帧。
