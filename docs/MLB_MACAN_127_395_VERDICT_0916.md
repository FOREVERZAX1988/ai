# Macan 0x127 / 0x395 —— 握手信号嫌疑排除（Task 2 结论, 0916）

> 背景：用户在握手逻辑深挖中再次提出 0x127(295) 与 0x395(917) 是否雷达怀疑信号。
> 数据源：route 0075(纯OP/坏) vs 0078(融合/好) seg0 rlog 逐帧，bus2(雷达) 原始字节直方图。

## 一、结论（一句话）
**0x127 和 0x395 都不是影响点火故障的握手信号。** 它们在好路由(0078)与坏路由(0075)
雷达侧(bus2)的字节分布基本一致 —— 握手诊断关键差异根本不在这两帧上（真正差异在 ACC_04 charisma 1→2、ACC_05 st 2→7）。

## 二、0x395 (917) —— 雷达状态/诊断帧（10Hz）
原始帧典型：`10 [4bit counter循环] 12/22 00 [b4漂移] [b5漂移] [b6漂移] 1c`
| 字节 | 0075 坏 直方图(radar bus2) | 0078 好 直方图(radar bus2) | 判定 |
|------|--------------------------|---------------------------|------|
| b2（0x12=18, 0x22=34, 0x62=98 状态档） | {**18:608**, 82:4} | {**18:608**, 82:4, 98:1} | 几乎一致：b2=0x12 为主 |
| b7 | {76:8, 204:33, **220:571**} | {12:1, 76:8, 204:34, **220:570**} | 一致（0xdc=220 恒定为主） |
- b1 稳定 4bit counter；b2=0x12(=18) 为主态，仅末段几次 0x52(82)/0x62(98)（非故障翻转）。
- **结论：0x395 是雷达自身周期性状态/诊断帧，好/坏路由字节级一致，不含故障触发信息。**

## 三、0x127 (295) —— 恒定状态/环境字（20Hz）
原始帧典型：`00[b1]49 3c 78 ee 00 00`（b1 为唯一变动字节）
| b1 | 0075 坏 直方图 | 0078 好 直方图 |
|----|---------------|---------------|
| 0x00 | 0 | **71** |
| 0x10 | 0 | **295** |
| 0x20 | **2851** | **2480** |
| 0x40 | 190 | 192 |
| 0x80 | 22 | 27 |
| 0x80+ 组合 | — | — |
- b1 主值都是 0x20(32)；0x00/0x10 仅在好路由点火初期短暂出现（~0.5% 量级），
  与 0x20 的切换是点火自检/ACC状态档的常变位，不是"雷达是否可用"的手flag。
- **结论：0x127 为近恒定 ACC/环境状态字，0x20 为主，非握手帧，非故障帧。**
  与既有文档(0909 MLB_MACAN_UNDEFINED_0x127_0x395)一致。

## 四、关键补强（为何可以彻底排除）
- 若 0x127/0x395 是"雷达登记/握手"信号，则**断开应答的坏路由必然在字节上显著异于好路由**。
  实测两者几乎 0 差异 → 它们不参与"雷达失联→故障"判定。
- 真正驱动故障的是 ACC_04/ACC_05/ACC_02 的状态位（见 HANDSHAKE 结论文档），
  即雷达在 9.25s 自报 charisma=2 / st=7。

## 五、任务2 收尾
- 0x127：维持"环境/状态字"定性，无实用值（除 ~20Hz 状态档参考）。
- 0x395：维持"雷达状态/诊断帧"定性，其 4bit counter 可作 10Hz 时基辅助。
- **两者均无需 OP 模拟，也不是纯OP报错的修复点。** 修复应回到 Task1 的三大方向
  （CAN2 模拟应答 / UDS 停用 radar / OP 不把 radar 故障当作 accFaulted）。

### 6.3 铁证
0x127 在故障前(9.212)与故障后(9.311)均为 `0020493c78ee0000`，**字节零变化**；
且好/坏路由该值一致。→ **0x127 不是握手/触发帧，2 号结论维持（环境/状态字）。**
0x395 为 10Hz 雷达自身状态/诊断帧，字节分布在好/坏路由几乎一致 → **维持"雷达状态/诊断帧"，非握手帧。**
